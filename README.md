# 序日 · 日程与项目管理

版本 1.1：淡粉主题、紧凑月历、项目任务与日程同步，数据保存到本机文件。单设备使用，无需账号、数据库或第三方运行依赖。

## Windows 启动

1. 从 https://nodejs.org/ 安装 Node.js **LTS**（20 或以上版本）。
2. 从 GitHub 的 **Code → Download ZIP** 下载项目，右键压缩包 → **全部解压**。
3. 打开解压后的项目文件夹，双击 **`start-windows.cmd`**。
4. 浏览器会打开 `http://127.0.0.1:3000`。如果没有自动打开，手动输入该地址。
5. **保持启动窗口打开**。停止时在启动窗口按 `Ctrl+C`。

也可在包含 `package.json` 的文件夹打开终端运行：

```bash
npm start
```

不需要 `npm install` 或构建。不要双击 `index.html` 启动；文件保存功能依赖本机 Node.js 服务。

## 从旧版本更新

1. 在旧页面的「数据与备份」中先导出一份备份。
2. 在旧版启动窗口按 `Ctrl+C`，停止旧服务。仅刷新网页不会更新已经运行的服务代码。
3. 下载、解压新版本，双击新版 `start-windows.cmd`。
4. 使用**原来的浏览器和地址**（包括原来的端口）打开网页，以便读取旧版浏览器数据。
5. 如果 `D:\datejob\data.json` 尚不存在，首次打开会自动把该浏览器的旧数据迁移到文件；迁移成功前不会删除浏览器里的旧副本。
6. 如果数据文件已经存在，文件中的记录优先加载；检测到尚未迁移的浏览器旧数据时，页面显示「迁移旧数据」，点击后可确认合并。相同编号以旧数据为准，请按需选择迁移。
7. 如果换了浏览器或地址，用之前导出的 JSON 备份在「数据与备份」中导入。

升级应用、移动项目文件夹和重新下载 ZIP 不会删除 `D:\datejob` 中的数据。请保留该目录。

## 数据保存在哪里

在 **Windows 电脑本机启动**时，默认自动创建：

```text
D:\datejob\
├── data.json           当前全部项目、任务、日程、备注和完成状态
└── data.previous.json  上一次成功保存的数据（第二次保存起生成）
```

「datejob」是文件夹，里面的 `data.json` 是数据文件。无需手动创建文件或粘贴 JSON。

每次操作由网页发送到本机服务，经校验后写入临时文件、刷新到磁盘，再替换正式文件。服务确认成功后，界面才显示「已保存到文件」。写入失败会提示并保留原文件；不会偷偷改回只存浏览器。写入锁与版本检查避免多个页面相互覆盖。

关闭浏览器、清除网站数据、换浏览器，甚至重启 Node.js 服务后，仍会读取同一个数据文件。浏览器只保存少量视图偏好和旧版迁移标记；新的业务数据以磁盘文件为准。

左下角「数据与备份」会显示**实际数据文件路径**。文件位于**运行 Node.js 服务的电脑**：如果服务运行在云机器，写入的是云机器，不能直接写入你电脑的 D 盘。要满足 D 盘保存要求，请按上面的 Windows 步骤在自己的电脑启动。

没有 D 盘、磁盘已满或目录无写入权限时会报错。可以自行指定另一个目录：

```powershell
npm start -- --data-dir "D:\datejob"
```

也支持 `DATEJOB_DATA_DIR` 环境变量；命令行 `--data-dir` 优先。macOS、Linux 默认使用项目目录旁的 `datejob` 文件夹；当前云工作区为 `/workspace/datejob`。

## 项目、任务和日程

- **新增项目**：左侧「新建一个项目」或「我的项目」旁的 **+**，填写名称、目标、截止日期（选填）与颜色。
- **编辑与归档项目**：打开项目后，右上角编辑信息或归档。在左侧「已归档」中查看或恢复。归档保留已有任务和日程。
- **新增任务**：项目详情 →「添加任务」。可以先不安排时间；之后点击任务下方「安排时间」。
- **安排到日历**：给任务设置日期、开始与结束时间，自动出现在当天时间表。点击任务日期可跳转。
- **独立日程**：月历选择日期 →「添加日程」，关联项目选择「不关联项目 · 独立日程」。
- **完成、编辑与删除**：勾选方框、点击铅笔或垃圾桶。项目和日历共用同一条记录，所有修改双向同步；删除前会确认。
- **查看日期**：年月下拉框或左右箭头切换月份；「今天」返回当天。月历下方显示所选日期的时间表。
- **时间校验**：结束时间须晚于开始时间，跨天请拆成两条。未完成日程重叠时显示提示，仍可保存。
- **手机窄屏**：左上角三条横线展开项目栏。弹窗支持 `Esc` 关闭。

新安装默认从空白数据开始；旧版迁移带来的未修改示例仍可以「清除示例」，你自己新增或修改过的记录会保留。

同一服务的多个标签页会定期同步；其他页面更改数据时，正在编辑的旧表单会关闭并提示重新编辑。版本冲突的请求不会覆盖新数据。

## 备份与恢复

左下角「数据与备份」：

- **导出**：下载完整 JSON 备份，包含已归档项目和所有记录。导出文件默认位于浏览器的下载文件夹，不改变主数据文件的位置。
- **合并导入**：保留当前其他记录，同一编号以备份为准；重复导入不产生副本。
- **替换导入**：完全还原为备份内容，覆盖其他当前记录。请先导出当前备份。
- **校验**：拒绝损坏的文件、无效日期时间与不存在的项目关联。上限 5 MB、500 个项目、10000 条任务 / 日程。

导入成功也会写入 `data.json`，保存前的状态会保留到 `data.previous.json`。

若 `data.json` 损坏：

1. 先停止服务，保留一份当前损坏文件，以免丢失可恢复内容。
2. 把 `data.previous.json` **复制**一份，副本改名为 `data.json`，替换损坏文件；或使用另存的完整 JSON 备份作为 `data.json`。
3. 重新启动。应用不会自动重置损坏的数据。

正常使用时不要同时手动编辑数据文件。定期把整个 `D:\datejob` 文件夹或导出的 JSON 备份到其他位置。

## 常见问题

- **找不到 node / npm**：安装 Node.js LTS 后，重新打开终端或启动脚本。
- **找不到 package.json**：当前目录不对，应打开解压后包含该文件的项目文件夹。
- **端口被占用**：更新时先停止旧服务再启动新版；也可用 `npm start -- --port 3001`。新版不同端口使用同一数据目录，数据一致；旧版浏览器数据的自动迁移仍需要原来的地址。
- **连接或保存失败**：检查启动窗口是否仍在运行、数据目录是否可写，修复后重新操作。失败的表单输入会保留。
- **更新后读不到文件**：确认已经停止旧版静态服务、启动新版服务，并刷新网页。
- **浏览器数据被清除后看不到记录**：检查「数据与备份」路径、启动命令的数据目录和运行服务的电脑是否正确。不要删除旧数据文件重新开始。

## 开发与验证

```bash
npm test
```

运行 10 项数据逻辑检查及 9 项磁盘存储检查，覆盖日期、记录同步、真实写盘、备份、并发冲突、损坏文件和写入失败保护（POSIX 目录权限检查在 Windows 跳过）。

真实浏览器检查需要 Python 3.10+ 和 Playwright，仅开发测试需要：

```bash
python3 -m pip install -r requirements-dev.txt
python3 -m playwright install chromium
npm run test:browser
```

Windows 使用 `python` 时，将前两行的 `python3` 改为 `python`，最后执行 `python -u tests/browser_test.py`。

测试使用随机端口、独立临时数据目录和浏览器资料，不修改 `D:\datejob` 或现有数据。实际检查项目任务同步、备份、旧版迁移、清空浏览器存储与重启服务后的恢复、写盘失败、手机布局及 1366×768 屏幕中月历和首条日程的位置。截图保存在已被 Git 忽略的 `test-results/`。

| 文件 | 用途 |
| --- | --- |
| `start-windows.cmd` | Windows 双击启动入口 |
| `server.mjs` | 本机网页与数据 API 服务 |

| `styles.css` | 淡粉主题和紧凑布局 |
| `tests/` | 数据、磁盘和真实浏览器测试 |

服务面向本机使用，不提供账号登录、云同步或多人协作。
