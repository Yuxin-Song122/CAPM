# 序日 · iPhone 与电脑日程 PWA

版本 1.2.3：以 iPhone 为主要使用设备，同时适配电脑。支持项目任务与月历、当天时间表联动，淡粉主题、设备本地保存、离线操作、备份导入导出。

## iPhone 安装与使用

需要先发布到 HTTPS 网站。项目包含 GitHub Pages 自动部署工作流；部署方式和实际网址核验步骤见 [HTTPS 部署与 iPhone 安装](docs/HTTPS部署与iPhone安装.md)。**源码已上传不等于网站已经发布成功，未验证的候选网址不能视为可用入口。**

1. 在 iPhone 上用 **Safari** 打开部署成功后的 HTTPS 网址。
2. 点击 Safari「分享」→「添加到主屏幕」。部分 iOS 版本在「更多」内；如果出现「作为 Web App 打开」，保持启用。
3. 名称保留为「序日」，点击「添加」。图标会出现在主屏幕。
4. 从主屏幕打开应用，保持联网，在底部「安装与离线」中确认显示 **离线已就绪**。
5. 打开飞行模式，关闭并重新打开应用；项目、任务、日期切换、完成状态、备份导入导出仍可使用。

建议先安装，再正式录入数据。如果已经在 Safari 标签页使用过，请先导出备份；部分 iOS 版本中主屏幕应用与 Safari 标签页的存储空间可能不同，安装后检查记录，必要时导入备份。

手机左上角菜单用于展开项目栏，菜单内可以打开项目、日历、系统提醒与备份。月历默认折叠，点击「展开月历」后才显示日期网格，点击「收起月历」可回到紧凑时间表。首页只保留今日安排、今日已完成两张卡片；顶部按钮在系统安全区之外额外留白。横屏保留菜单模式，弹窗和底部控件考虑屏幕安全区域。电脑上保留固定左侧项目栏。

## 两种数据保存方式

| 使用方式 | 主要保存位置 | 离线使用 | 与其他设备同步 |
| --- | --- | --- | --- |
| HTTPS PWA（iPhone 或电脑浏览器） | 当前设备的 IndexedDB | 首次联网完成离线缓存后支持 | 未实现 |
| Windows 本机 Node.js 文件版 | `D:\datejob\data.json` | 需要本机服务运行 | 未实现 |

PWA 不将项目或日程上传到网站。清除网站数据、卸载主屏幕应用或系统清理存储可能删除记录，请定期在「数据与备份」导出 JSON，并在 iPhone 分享/下载界面保存到「文件」。导入时在文件选择器中选择该 JSON，可合并或替换恢复，完成状态一并保留。

iPhone 无法直接写入电脑 D 盘。电脑文件版数据可先导出，再在 iPhone PWA 导入，反向亦然；这是**手动备份迁移**，不是自动同步。更换网站域名或路径后也应先备份再迁移。

## 系统提醒（需要单独部署推送后台）

新版提供提前 **2 小时、30 分钟、5 分钟**的后台推送方案。GitHub Pages 只托管前端，不能自行按时间发送通知。需要自己的 Cloudflare Workers、D1 数据库、Cron 定时任务、VAPID 密钥和配对码；部署步骤见 [后台提醒服务](push-backend/README.md)。

当前个人推送后台已部署到 `https://xuri-push.2832667234.workers.dev`，新版会预填此地址。配对码不在网站或仓库中，须从私密配置取得。

如果手机在 Wi-Fi 和蜂窝网络下均无法访问默认后台域名，可尝试 [Cloudflare Pages 免费备用入口](push-backend/pages-gateway/README.md)。它通过服务绑定连接同一个提醒 Worker，保留数据库、定时任务、推送密钥和配对码，应用本身的网址不变。此目录是备用方案的源码，**不代表备用入口已经部署**；部署需要账户的 Cloudflare Pages 编辑权限，实际域名和手机可达性必须另外验证。

部署后在主屏幕的「序日」→菜单→「系统提醒」中填写实际 HTTPS 后台地址和配对码，允许系统通知，再发送测试通知。iPhone 需要 iOS 16.4 或以上，必须从主屏幕应用启用。**显示「未连接推送后台」时，提醒并未启用。** 连接与安排同步成功也不代表已在真实 iPhone 验证送达，仍需测试通知和锁屏验收。

若无法连接，先点击同一设置页的「检查后台连接」。这项检查无需填写配对码或授予通知权限，在 Safari 普通页面也能执行；仅读取后台状态和公开推送配置，不上传任何项目、日程、配对码或设备令牌，不修改本地数据。结果显示后台是否可访问、当前网站来源、应用打开方式和通知权限。连接错误会区分读取配置、登记设备、同步安排等阶段，以及超时、HTTP 错误和非 JSON 响应。浏览器的网络错误本身仍无法精确区分 DNS、TLS、网络和来源限制；检查通过也不等于通知已经送达。

仅向自己的后台发送通知订阅和未完成定时日程的名称、开始时间；不会上传完整项目目标或备注。过去的提醒点不会补发。完成、删除或改期后的提醒安排需联网同步；离线期间后台可能仍按上一次安排推送。每次 Cron 一分钟检查一次，送达还受 Apple、网络、专注模式和系统设置影响，不保证秒级到达。

## 更新到新版并保留记录

保持当前网址、同一浏览器资料和当前主屏幕应用。联网后重新打开，出现「更新应用」时点击，页面底部显示 **v1.2.3** 即为新版。更新仅替换网页资源，未修改原来的 `xuri-device-v1` 数据库、项目记录或日程结构。**不需要卸载应用、清除网站数据或重置数据库**；这些操作可能丢失本机记录。建议更新前导出备份以便自留，但无需删除数据再导入。

自动化测试用旧版真实 Service Worker 和隔离的原始记录升级至新版，逐项比较完整 IndexedDB 快照、项目编号、任务备注、完成状态和 revision；这验证了升级路径，但不能代替你在个人 iPhone 上核对自己的记录。

**电脑与手机自动同步：未实现。** 没有账号或同步服务器，两台设备的记录不会自动合并。

## 验证范围

已提供纯静态 `/CAPM/` 子路径的真实浏览器自动化检查，覆盖 IndexedDB、离线重新打开与增改删、项目/日历联动、导入导出、关闭重开浏览器，以及 320/390/430px 和横屏布局。当前执行环境没有连接物理 iPhone，也没有可运行的 WebKit，**Chromium 的 iPhone 尺寸模拟不等于 Safari 或真机验证**。

真机请逐项检查：Safari 添加到主屏幕、图标与独立窗口、菜单开合、项目任务安排和勾选同步、飞行模式关闭重开后继续编辑、导出到「文件」及导入还原。网站实际部署成功后，仍需要在 iPhone 上完成这些验收，才能声称真机通过。

## 静态发布与测试

```bash
npm run build
npm run test:pwa
```

`dist/` 仅包含白名单网页、样式、图标和脚本，不包含 Node API、本机数据、Git 历史或测试备份。静态入口使用设备存储模式，所有路径相对部署目录，兼容 `/CAPM/` 子路径。

每次构建自动按应用资源内容生成缓存版本。新版本下载完成后，页面显示「更新应用」；点击后才激活更新，避免编辑过程中自动重载。本地 IndexedDB 独立于离线资源缓存，更新不会主动清空记录。首次离线准备失败时会提示，不能当成离线已就绪。

`npm run test:pwa` 需要 Python、Playwright 和 Chromium，使用独立临时配置，不修改个人数据。下文保留电脑文件版的使用说明。

## Windows 启动

1. 从 https://nodejs.org/ 安装 Node.js **LTS**（20 或以上版本）。
2. 从 GitHub 的 **Code → Download ZIP** 下载项目，右键压缩包 → **全部解压**。
3. 打开解压后的项目文件夹，双击 **`start-windows.cmd`**。
4. 浏览器会打开 `http://127.0.0.1:3000`。如果没有自动打开，手动输入该地址。
5. **保持启动窗口打开**。停止时在启动窗口按 `Ctrl+C`。

也可在包含 `package.json` 的文件夹打开终端运行：

```bash
npm start
```

不需要 `npm install` 或构建。不要双击 `index.html` 启动；文件保存功能依赖本机 Node.js 服务。

## 从旧版本更新

1. 在旧页面的「数据与备份」中先导出一份备份。
2. 在旧版启动窗口按 `Ctrl+C`，停止旧服务。仅刷新网页不会更新已经运行的服务代码。
3. 下载、解压新版本，双击新版 `start-windows.cmd`。
4. 使用**原来的浏览器和地址**（包括原来的端口）打开网页，以便读取旧版浏览器数据。
5. 如果 `D:\datejob\data.json` 尚不存在，首次打开会自动把该浏览器的旧数据迁移到文件；迁移成功前不会删除浏览器里的旧副本。
6. 如果数据文件已经存在，文件中的记录优先加载；检测到尚未迁移的浏览器旧数据时，页面显示「迁移旧数据」，点击后可确认合并。相同编号以旧数据为准，请按需选择迁移。
7. 如果换了浏览器或地址，用之前导出的 JSON 备份在「数据与备份」中导入。

升级应用、移动项目文件夹和重新下载 ZIP 不会删除 `D:\datejob` 中的数据。请保留该目录。

## 数据保存在哪里

在 **Windows 电脑本机启动**时，默认自动创建：

```text
D:\datejob\
├── data.json           当前全部项目、任务、日程、备注和完成状态
└── data.previous.json  上一次成功保存的数据（第二次保存起生成）
```

「datejob」是文件夹，里面的 `data.json` 是数据文件。无需手动创建文件或粘贴 JSON。

每次操作由网页发送到本机服务，经校验后写入临时文件、刷新到磁盘，再替换正式文件。服务确认成功后，界面才显示「已保存到文件」。写入失败会提示并保留原文件；不会偷偷改回只存浏览器。写入锁与版本检查避免多个页面相互覆盖。

关闭浏览器、清除网站数据、换浏览器，甚至重启 Node.js 服务后，仍会读取同一个数据文件。浏览器只保存少量视图偏好和旧版迁移标记；新的业务数据以磁盘文件为准。

左下角「数据与备份」会显示**实际数据文件路径**。文件位于**运行 Node.js 服务的电脑**：如果服务运行在云机器，写入的是云机器，不能直接写入你电脑的 D 盘。要满足 D 盘保存要求，请按上面的 Windows 步骤在自己的电脑启动。

没有 D 盘、磁盘已满或目录无写入权限时会报错。可以自行指定另一个目录：

```powershell
npm start -- --data-dir "D:\datejob"
```

也支持 `DATEJOB_DATA_DIR` 环境变量；命令行 `--data-dir` 优先。macOS、Linux 默认使用项目目录旁的 `datejob` 文件夹；当前云工作区为 `/workspace/datejob`。

## 项目、任务和日程

- **新增项目**：左侧「新建一个项目」或「我的项目」旁的 **+**，填写名称、目标、截止日期（选填）与颜色。
- **编辑与归档项目**：打开项目后，右上角编辑信息或归档。在左侧「已归档」中查看或恢复。归档保留已有任务和日程。
- **新增任务**：项目详情 →「添加任务」。可以先不安排时间；之后点击任务下方「安排时间」。
- **安排到日历**：给任务设置日期、开始与结束时间，自动出现在当天时间表。点击任务日期可跳转。
- **独立日程**：月历选择日期 →「添加日程」，关联项目选择「不关联项目 · 独立日程」。
- **完成、编辑与删除**：勾选方框、点击铅笔或垃圾桶。项目和日历共用同一条记录，所有修改双向同步；删除前会确认。
- **查看日期**：年月下拉框或左右箭头切换月份；「今天」返回当天。月历下方显示所选日期的时间表。
- **时间校验**：结束时间须晚于开始时间，跨天请拆成两条。未完成日程重叠时显示提示，仍可保存。
- **手机窄屏**：左上角三条横线展开项目栏。弹窗支持 `Esc` 关闭。

新安装默认从空白数据开始；旧版迁移带来的未修改示例仍可以「清除示例」，你自己新增或修改过的记录会保留。

同一服务的多个标签页会定期同步；其他页面更改数据时，正在编辑的旧表单会关闭并提示重新编辑。版本冲突的请求不会覆盖新数据。

## 备份与恢复

左下角「数据与备份」：

- **导出**：下载完整 JSON 备份，包含已归档项目和所有记录。导出文件默认位于浏览器的下载文件夹，不改变主数据文件的位置。
- **合并导入**：保留当前其他记录，同一编号以备份为准；重复导入不产生副本。
- **替换导入**：完全还原为备份内容，覆盖其他当前记录。请先导出当前备份。
- **校验**：拒绝损坏的文件、无效日期时间与不存在的项目关联。上限 5 MB、500 个项目、10000 条任务 / 日程。

导入成功也会写入 `data.json`，保存前的状态会保留到 `data.previous.json`。

若 `data.json` 损坏：

1. 先停止服务，保留一份当前损坏文件，以免丢失可恢复内容。
2. 把 `data.previous.json` **复制**一份，副本改名为 `data.json`，替换损坏文件；或使用另存的完整 JSON 备份作为 `data.json`。
3. 重新启动。应用不会自动重置损坏的数据。

正常使用时不要同时手动编辑数据文件。定期把整个 `D:\datejob` 文件夹或导出的 JSON 备份到其他位置。

## 常见问题

- **找不到 node / npm**：安装 Node.js LTS 后，重新打开终端或启动脚本。
- **找不到 package.json**：当前目录不对，应打开解压后包含该文件的项目文件夹。
- **端口被占用**：更新时先停止旧服务再启动新版；也可用 `npm start -- --port 3001`。新版不同端口使用同一数据目录，数据一致；旧版浏览器数据的自动迁移仍需要原来的地址。
- **连接或保存失败**：检查启动窗口是否仍在运行、数据目录是否可写，修复后重新操作。失败的表单输入会保留。
- **更新后读不到文件**：确认已经停止旧版静态服务、启动新版服务，并刷新网页。
- **浏览器数据被清除后看不到记录**：检查「数据与备份」路径、启动命令的数据目录和运行服务的电脑是否正确。不要删除旧数据文件重新开始。
